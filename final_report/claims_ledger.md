| C0011 | Front matter | Data science pipeline descriptions contain dependencies that can be checked before an execution engine is invoked. This project implements a domain-specific language and compiler front-end for expressing such descriptions as one named pipeline. The language supports dataset declarations, cleaning, column selection and dropping, percentage-based partitions, model declarations and evaluation requests. A regular-expression lexer produces tokens with source coordinates. A hand-written recursive-descent parser constructs a dataclass-based abstract syntax tree. Semantic analysis traverses the tree with a symbol table to enforce declaration, ordering, column and partition constraints. A lowering stage produces opcode-and-argument instructions. Four optimizer passes remove instructions after the final evaluation, eliminate unused training declarations, merge adjacent drops and collapse adjacent duplicate cleaning or selection instructions. A symbolic executor formats the optimized instructions as a readable trace; no dataset contents are read and no numerical model training or accuracy calculation is performed. A command-line interface exposes intermediate results, while a Streamlit dashboard presents the same compiler stages interactively. Validation records 267 passing tests and the outcomes of all 20 supplied example programs. Optimizer tests compare symbolic evaluation records, test transformation boundaries and check repeated optimization. Recorded benchmark measurements are examined by stage, time per statement and instruction reduction. The results demonstrate an inspectable compiler pipeline within a deliberately restricted language, with explicit limits on execution, schema validation and error recovery. | Phase2 cover; abstract verified against final evidence | Matched |
